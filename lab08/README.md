Бизнес-правила:

1. Каждый спор относится к существующему заказу.
   Реализация: внешний ключ fk_disputes_order на olist.orders(order_id).

2. Каждый спор имеет причину.
   Реализация: поле reason объявлено NOT NULL.

3. Причина спора не может быть пустой строкой.
   Реализация: CHECK ck_disputes_reason.

4. Статус спора может принимать только значения:
   open, in_progress, resolved, rejected.
   Реализация: CHECK ck_disputes_status.

5. Каждое сообщение обязательно относится к существующему спору.
   Реализация: внешний ключ fk_dispute_messages_dispute.

6. Сообщение может быть связано с существующим продавцом.
   Реализация: внешний ключ fk_dispute_messages_seller на olist.sellers(seller_id).
   Поле seller_id допускает NULL, так как сообщение может быть не от продавца.

7. Текст сообщения обязателен.
   Реализация: message_text NOT NULL.

8. Каждая запись истории статусов относится к существующему спору.
   Реализация: внешний ключ fk_dispute_status_history_dispute.

9. Статус в истории также ограничен набором допустимых значений.
   Реализация: CHECK ck_dispute_status_history_status.

10. Для одного спора нельзя зарегистрировать две смены статуса в один и тот же момент времени.
    Реализация: UNIQUE (dispute_id, changed_at).
